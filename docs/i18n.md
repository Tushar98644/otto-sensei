# Languages (i18n)

Plan for serving Otto in Spanish (`es`), Portuguese–Brazil (`pt-BR`), French (`fr`) and German (`de`). English stays the default. Decided 2026-11-25: translate everything — website, app, resume engine, emails and jobs — one shippable phase at a time, with English output unchanged at every step.

## Decisions

| Question      | Decision                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| URL shape     | English unprefixed (URLs never change). Others prefixed: `/es`, `/pt-br`, `/fr`, `/de`. `/en/*` 308s to the unprefixed path.                                                                                                                                                                                                                                                                 |
| Slugs         | English slugs under the prefix (`/es/resume-builder`).                                                                                                                                                                                                                                                                                                                                       |
| Routing       | Every page under `src/app/[lang]/`, root layout `src/app/[lang]/layout.tsx` with `<html lang>` from `next/root-params`. The proxy rewrites unprefixed paths to `/en/…`. Outside `[lang]`: `api/`, `auth/`, metadata routes (`sitemap`, `robots`, `llms*`, OG image, icons) and `p/` (own root layout, the portfolio's language).                                                             |
| App language  | Not in the URL. `user_settings.locale`, mirrored to an `otto_lang` cookie; the proxy rewrites app paths (`/dashboard`, `/studio`, `/account`, `/reminder`, `/s`, `/extension`) to that locale. `/{locale}/<app path>` sets the cookie and 307s to the unprefixed path. No Accept-Language redirects.                                                                                         |
| Library       | Small typed layer of our own, no dependency. English messages `as const` are the source of truth; other locales `satisfies Translation<typeof en>`, so a missing key fails `tsc`. `{var}` interpolation, plural objects via `Intl.PluralRules`, `<b>`/`<link>` rich-text tags. next-intl (4.16, supports Next 16) is the fallback; keep a similar API (`getMessages`, `useMessages`, `fmt`). |
| Client cost   | Marketing pages get no provider: client islands receive translated strings as props. App layouts pass only their namespaces to a client provider, with a byte budget test.                                                                                                                                                                                                                   |
| Language axes | UI locale, resume language (`lang` in the resume JSON, detected, user can override) and job-post language are separate.                                                                                                                                                                                                                                                                      |
| AI prompts    | System prompts stay English and byte-stable for the cache; the language goes in the user message (`<languages resume ui post/>`).                                                                                                                                                                                                                                                            |
| Translation   | AI translation with a glossary, neutral Latin American Spanish, informal address (tú, você, tu, du); native review of top pages before heavy promotion.                                                                                                                                                                                                                                      |
| Publishing    | Per locale and per page; the language setting in the app stays hidden until the whole app is translated.                                                                                                                                                                                                                                                                                     |

## Phases

Each phase ships to main on its own and leaves English byte-identical.

| Phase               | What                                                                                                                                                                                                                           | Size      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------- |
| P0 Foundations      | `src/i18n/*` core and tests, golden English HTML check, move under `[lang]` with only `en` enabled, proxy rewrite, `user_settings.locale`, cookie endpoint, privacy-policy cookie line, regenerated route baselines            | M         |
| P1 Content language | Detector, resume `lang`, lint language packs (neutral checks only for non-English until packs land), import-parser tables, AI language tags and guards, moderation lists, PDF/DOCX labels                                      | L         |

| P3 App              | Extract dashboard, studio, portfolio, account, API errors, `Intl` cleanup; translations; then show the language setting                                                                                                        | XL        |
| P4 Emails           | Resend builders take a locale; sign-in code email per locale                                                                                                                                                                   | S–M       |
| P5 SEO long tail    | Comparisons, ATS guides, resume examples per locale                                                                                                                                                                            | L content |
| P6 Jobs             | Post-language detection, job-language preference, per-language seniority patterns, multilingual title matching                                                                                                                 | M–L       |

## How it works (P0, as built)

**Locales** (`src/i18n/config.ts`): `LOCALES` lists all five; `ENABLED_LOCALES` is the switch that routes and prerenders one (only `en` today). Each locale has a URL segment (`pt-BR` → `pt-br`), an `Intl` tag (`en` → `en-US`, so English numbers and dates don't change; `es` → `es-419`) and an Open Graph locale. `matchLocale()` maps any BCP-47 tag to ours (`es-MX` → `es`, `pt-PT` → `pt-BR`).

**Routes.** Every page is under `src/app/[lang]/`. The root layout `src/app/[lang]/layout.tsx` sets `<html lang>` (from the segment; `getMessages` reads it through `next/root-params`), returns only enabled locales from `generateStaticParams` and 404s any other segment. Its `generateMetadata` passes `src/app/opengraph-image.tsx` on by hand: that file sits above the layout now, and a layout's `openGraph` would otherwise replace its image. Portfolios have their own root layout, `src/app/p/[slug]/layout.tsx` (English for now; later the portfolio's language), and both share `src/components/site/root-document.tsx`. Outside `[lang]`: `api/`, `auth/`, `p/`, `sitemap.ts`, `robots.ts`, `llms.txt`, `llms-full.txt`, `opengraph-image`, `icon.svg`, `apple-icon`, `global-not-found.tsx` and `global-error.tsx` (Next needs it at the app root; it keeps `lang="en"` until P3 moves its copy into messages).

**404.** A URL no route matches gets `src/app/global-not-found.tsx` (`experimental.globalNotFound`): a static page that draws the old 404 in its own English document, since a root layout under `[lang]` can't hold the app-wide one. A `[lang]/[...rest]` catch-all calling `notFound()` was tried and dropped: under a root layout with a dynamic segment, Next answers it with an empty error shell (status 404, the page drawn only in the browser), checked on a production build. `notFound()` inside a page still renders the nearest `not-found.tsx` (`src/app/[lang]/not-found.tsx`), as before. When other languages go live, a localized 404 needs one of: global-not-found reading a locale header the proxy sets (it would turn dynamic), or a Next release that renders the catch-all on the server. Paths the proxy never sees (`/api/…`, `/p/a/b`, missing files) can still reach `[lang]` with a segment that isn't a locale; the root layout answers those with a bare 404.

**Proxy** (`src/proxy.ts`, rules in `src/i18n/routing.ts`). Locale first; then the sign-in redirects, session refresh and `/login` variants run unchanged on the visible path without its prefix; then a rewrite to `/{segment}{path}`:

- `/en` and `/en/*`: 308 to the unprefixed path.
- `/{live locale}/{app path}`: sets `otto_lang` and 307s to the unprefixed app path (`/en/dashboard` is the way back to English).
- `/{live locale other than en}/{public path}`: served as is.
- App paths (`/dashboard`, `/studio`, `/account`, `/reminder`, `/s`, `/extension`): `/{otto_lang if live, else en}/…`.
- Everything else: `/en/…`. A prefix that isn't live is an unknown path (`/es/pricing` → `/en/es/pricing` → 404), and its cookie is never set.
- Untouched: `api/`, `auth/`, `p/`, `_next/`, the folders and files of `public/`, and the root metadata routes. `src/i18n/routing.test.ts` walks `public/` and `src/app/` so a new folder can't be hidden.

**Messages** (`src/i18n/messages/`). `en/<namespace>.ts` (`as const`) is the source of truth, listed in `en/index.ts`. Another locale adds `<locale>/<namespace>.ts` (`satisfies Translation<Messages["<namespace>"]>`) and one line in its `index.ts`; a namespace it hasn't translated reads in English. Namespaces, all empty but `common` until their phase: `common`, `site`, `home`, `pricing`, `product`, `login`, `seo` (P2, P5); `dashboard`, `jobs`, `applications`, `letters`, `interview`, `studio`, `portfolio`, `portfolioContent`, `account`, `share`, `api` (P3); `emails` (P4); `lint` (P1, translated in all five: the resume checks' messages, help and review, for the UI to read).

**Reading them.** Server Components (and `generateMetadata`) call `getMessages(ns)`, `getLocale()` and `getFormat()` from `src/i18n/server.tsx`, which read the `[lang]` root param; route handlers and server actions can't (Next doesn't allow root params there), so they take the locale from the cookie or the account. Client components below `<MessagesFor namespaces={[…]}>` call `useMessages(ns)`, `useLocale()` and `useFormat()` from `src/i18n/client.tsx`; only the named namespaces reach the browser. Helpers: `fmt()` fills `{name}` (the English template types its values), `formatFor(locale).plural(forms, count)` picks a form with `Intl.PluralRules`, `rich()` turns `<b>` and `<link>` into elements, and `formatFor(locale)` keeps one `Intl` formatter per locale and options.

**Checks.** `src/i18n/messages.test.ts` runs `checkMessages` (`src/i18n/check.ts`: keys, placeholders and tags match English, each language's plural forms, no empty or still-English text) over every locale file, and keeps an enabled locale complete. Vitest stubs `next/root-params` with `src/i18n/testing.ts`.

**Dashboard (P3, first slice).** `src/app/[lang]/dashboard/layout.tsx` wraps the shell in `<MessagesFor namespaces={DASHBOARD_NAMESPACES}>` (`dashboard`, `jobs`, `applications`, `interview`, `letters`; `namespaces.test.ts` keeps the serialized payload under a byte budget, about 43 KB in English and 50 KB in German today). Page titles come from `page-title.ts`. Client components read `useMessages(ns)` and `useFormat()`; pure helpers take the messages and `Format` as arguments, and tests pass the English ones from `src/components/dashboard/messages-testing.tsx`. Components the studio or the marketing `/account` page also render (`status-menu`, `mark-applied`, `looking-for-card`, `occupation-search`, `guide-video`) don't call `useMessages`: they take their words as props, with English defaults, or stay English for now. A word that reads the same in a language (German "Jobs", French "Portfolio") goes in `SAME_AS_ENGLISH` in `messages.test.ts`.

**Portfolio, Account and share pages (P3).** A `MessagesProvider` inside another adds its namespaces to the outer one's (same locale only), so a page sends just what it adds. The portfolio editor (`/dashboard/portfolio`) adds `portfolio` and `portfolioContent` (about 21 KB in English, 24 KB in French and German); `/account` and `/dashboard/account` add `account` (about 18 KB, 21 KB); `/s` sends `share` (about 2 KB). Each has a `namespaces.test.ts` budget. The extension connect and reminder pages have no provider: their server pages pass `account.extension.connect` and `account.reminder` as props, with the locale. Store functions that toast outside React take their words as an argument (`savePortfolio(patch, words)`); the content autosave gets them from `useContentSaveWords`. Prices stay USD, written the reader's way (`components/account/local-prices.ts`; in English they match `lib/billing/prices`). The delete-account confirm word is translated (ELIMINAR, EXCLUIR, SUPPRIMER, LÖSCHEN). Tests render with `withMessages(locale, namespaces, node)` from `src/i18n/messages-testing.tsx`.

**Public portfolios.** `/p/[slug]` reads the language set on the owner's resume (`PublicPortfolio.lang`, from the snapshot): `<html lang>`, the Open Graph locale, the title and description fallbacks and the share image's label follow it; a page with none set, or a missing page, stays English. The owner's own words, and each design's own copy, are never translated by Otto.

**App language.** `user_settings.locale` (null: never chosen; a check allows the five codes) and `PUT /api/language` with `{ "locale": "en" }` (signed in, same-site JSON, 30 changes an hour) save it and set `otto_lang` (httpOnly, a year). Only live locales are accepted, and the app doesn't offer the choice yet.

**Golden HTML.** Build `main`, `bun scripts/golden-html.ts save <folder>`; build your change, `bun scripts/golden-html.ts compare <folder>`. It compares every prerendered English page after taking out build hashes and Next's own payload, and lists what differs.

## Content language (P1, as built)

**Detector** (`src/lib/i18n/detect.ts`): function words, resume vocabulary, word endings and accents scored for en, es, pt, fr and de. `detectLanguage(text)` gives `{ lang, confidence }`, `"unknown"` when unsure; `languageOf(text, fallback)` falls back. All-caps words ("MIT", "LA") don't count, so English resumes with foreign names stay English.

**Resume `lang`** (`src/lib/resume/lang.ts`): optional in the resume JSON (`en es pt fr de`). `resumeLang(resume)` reads it, else detects from the person's own words, else English. Imports (file, JSON Resume, LinkedIn) and drafts store a detected language other than English, so English resumes keep their shape. `setResumeLang(resume, lang | null)` is for the language control (null goes back to detecting).

**Lint** (`src/lib/lint/lang/`): one `LintLanguage` pack per language; `CHECK_LANGS` says which languages each check runs for. Length, numbers, repeats and full stops run for every language; `tense` and `passive` are English-only; word checks need the pack's lists. Noun-style lines ("Gestión de…", "Leitung von…") aren't weak. French elisions are their own tokens. Issues carry a non-enumerable `messageId` and `params`; `issueText(issue, messages, locale)` rebuilds the message from the `lint` namespace, and a test keeps the English namespace identical to `message`.

**Import parser** (`src/lib/resume/sections-lang.ts`, `date-words.ts`): headings, month names, present words ("actualidad", "atual", "aujourd'hui", "heute") and range words ("a", "até", "au", "bis") for all four languages. English matches first; "out", "set" and "ago" count as months only before "/" or ".".

**AI.** System prompts stay English and byte-stable; their plain-English line also reads a `<languages resume ui post/>` tag that opens the user message, left out when everything is English. Resume lines and summaries follow the resume's language, notes and questions the app's (`otto_lang`, live locales only), letters, messages and interview questions the post's (detected, else the resume's); interview stories stay in the resume's language so the honesty checks can compare them. Guards add each language's stock phrases, unbacked phrases, blank words, number words and pronouns; outside English the number guard reads "99,9 %", "12 000" and "1.250,5". The moderation pre-check has word lists for all four languages. Speech to text takes an optional `language` form field.

**PDF and Word.** Default headings, extras titles, the document title and its language tag (`<Document language>`, `w:lang`) follow the resume's language; the person's own headings win. A letter's date and title follow the letter's language.

## Guardrails

- `tsc` checks every locale has every key; a vitest suite checks placeholder and tag parity, plural categories, no empty or untranslated strings.
- An `otto/no-literal-copy` lint rule, ratcheted per extracted folder.
- Golden English HTML: prerendered pages must be byte-identical before and after each extraction step.
- `next build` must keep marketing routes static or ISR.
- A lint rule bans literal `"en-US"` in `Intl` calls outside an allowlist.

## Known gaps today

- The lint packs, heading tables and guard lists need a native speaker's review.
- The upgraded-verb check ("Helped with" written as "Led") and job-title and school words in the import parser are English-only.
- Demo-mode answers and the warnings under AI results are English until P3.
- Still English in the portfolio and account areas: the 15 designs' own copy (section labels such as "Get in touch", Gazette's newspaper lines), the content Otto fills in for a new page ("Open to work", "Building"), the sign-in form and dialog, the add-credit dialog, `BillingNote`, the invite prompt, the share dialog and link list, the GitHub connect pieces, the calendar feed, the work-profile form and API error messages. `/p/[slug]/not-found` and its skip link stay English.
- Job title vectors (JobBERT-v2) are English-only.
- German text runs about 30% longer: check buttons and mascot bubbles. A 250-word German letter fits one page in every template (`src/lib/pdf/lang.test.ts`); no template has a narrow heading column.
